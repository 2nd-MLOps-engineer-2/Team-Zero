# 누락 자료·미구현 보완 업무 — Bronze → Silver → Gold

이 문서는 빠진 자료를 단순히 “없음”으로 남기지 않고 **누가 확보·작성·구현·검증할지** 정한다. 현재 요청은 이 업무 지시를 추가하는 것이며 아래 항목을 실제 수행·완료했다는 뜻은 아니다. 기존 체크북 47개 ID는 유지하고 보완 업무에 M01~M14를 부여한다.

## 공통 수행 원칙

1. 제공된 75파일과 현재 구현을 먼저 확인한다. 이미 있는 것은 재사용하고 부족한 내용만 추가한다.
2. **없는 문서·계약·코드·검사는 담당자가 작성·구현한다.** 원천 데이터·접근 권한이 필요한 경우 필요한 입력을 정확히 요청하고 독립 작업은 계속한다.
3. 원본은 확보해야 하는 자료다. Silver에서 거꾸로 만들어 Bronze라고 하거나 공시일·원문·과거 덤프를 지어내지 않는다.
4. 각 역할은 `docs/roles/`에 보완 ID·상태·산출물·검사·미해결을, 다른 역할 요청은 `docs/handoffs/`에 남긴다. 합의가 필요한 계약은 제안과 확정을 구분한다.
5. 실제 자료 미확보, 구현 미착수, 검증 미실행, 검증 실패를 구분한다. 대체 자료·합성 자료는 목적과 한계를 표시한다.
6. 고정 인계본은 수정하지 않는다. 추가 입수 자료의 출처·수집일·해시를 별도로 기록하고 공개 가능 범위를 확인한다. 자료 요청·인계 기록은 상대에게 실제 메시지를 보냈다는 뜻이 아니다.

## 4. 역할별 반드시 추가할 내용

### A 이어진 — 화면과 표시

M08·M09·M12·M13·M14를 담당 범위에서 수행한다. 특히 Bronze 미확보, Silver 검토·격리, Gold 계산 불가를 서로 다른 상태로 표시하고, 공시일·재무 기간·원/주/%/%p·지표 근거를 유지한다. B/C가 아직 제공하지 않은 필드는 정확한 요청으로 남기고 임의 수치로 채우지 않는다. API 대기 중에도 합성 fixture 기반 화면·필터·오류/빈 결과 검사를 진행한다.

### B 설호현 — 자료 확보·저장·실행·API

M01·M03~M06·M08·M09·M11·M12·M14를 담당 범위에서 수행한다. 누락 입력을 확보 명세로 관리하고, 실제 3레이어 Delta와 MySQL·API·버전·복원법을 구현한다. 외부 원본이 필요한 Bronze와 제공 CSV로 가능한 Silver/Gold 작업을 분리해 병렬 진행한다. C의 계산·기간 규칙을 저장 과정에서 변경하지 않는다.

### C 김형준 — 진단·정의·분석·검증

M01~M03·M05~M10·M14를 담당 범위에서 수행한다. 최초 오염 원본 증빙과 C 통합 AS-IS를 구분하고 표준 사전·변환·미해결 정책을 필요한 범위만 보완한다. 기간·계정·수급·시점 검증, 실적·현금흐름·시장 지표, 동반 개선·괴리 규칙, 시각화·AI 입력 규격을 작성·구현한다. 실제 Silver로 지금 가능한 분석은 원본 확보를 기다리지 않는다.

## 5. 보완 상태 기록

각 역할의 진행 기록에 다음 필드를 추가하고 구현 시작 시 항목별 상태를 갱신한다.

```text
보완 ID / Bronze·Silver·Gold·공통:
현재 상태: 입력 미확보 / 문서 미작성 / 구현 중 / 검증 미실행 / 실패 / 완료
담당 범위와 상대 역할 요청:
재사용한 파일·기준 SHA·데이터 버전:
추가한 문서·코드·자료 위치:
실제 실행한 검사·결과·증빙:
남은 입력·판단·한계:
```

“없어서 못 함”만 쓰고 종료하지 않는다. 필요한 자료를 항목별로 특정하고, 담당자가 만들 수 있는 내용은 작성·구현·검증해 전달한다. 미확보 자료를 지어내거나 전체 프로젝트를 기다리게 만들지 않는다.
