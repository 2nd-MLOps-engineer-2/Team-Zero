실제 준비 자료는 [데이터 안내](data-guide.md)와 [전체 컬럼 사전](data-catalog.md)에 연결했다. `data/03_C_integration_20261014/`의 Silver·Gold·사전·DDL·코드·이전 검증 기록을 재사용한다. Bronze 원본·덤프 미포함과 과거 AS-IS의 범위를 구분한다. 자료가 올라온 사실만으로 아래 구현·검증 항목을 완료 처리하지 않는다.

## A — 이어진 / 프론트엔드

입력: B의 API 규격·샘플 응답 + C의 지표 설명·그래프 예시.

- [ ] **A01 화면 구조와 사용자 동선:** 기업·기간 선택에서 결과 확인까지 흐름 정리.
- [ ] **A02 공통 필터와 조회 상태:** 기업·기간·보고서 필터, 로딩·오류·빈 결과.
- [ ] **A03 주요 재무 지표 카드:** 매출·영업이익·순이익·영업현금흐름의 값과 기간.
- [ ] **A04 주가·시장 비교:** 주가·지수, 비교 기간과 축의 의미.
- [ ] **A05 실적·현금흐름 비교:** 같은 누적기간의 손익·현금을 C의 설계로 표현.
- [ ] **A06 외국인·기관 수급:** 순매수 수량·보유비율 구분, 주·원·% 단위.
- [ ] **A07 괴리와 추가 검토:** 분류·근거 수치·관련 보고서·공시 표시.
- [ ] **A08 API 연결:** B 규격 연결과 필터 변경에 따른 갱신.
- [ ] **A09 품질·출처:** NULL·0·미연결 구분, 공시일·재무 기준·검토 사유.
- [ ] **A10 수치·사용성 검수:** API와 화면 대조, 그래프·범례·반응형 검수.

제출: 화면 설계·프론트엔드 코드·연동 화면·수치 대조. 완료: 필터가 동작하고 API와 숫자가 일치하며 단위·공시일·결측 사유가 보인다.

## B — 설호현 / 백엔드

입력: 교환 원본·명세서 + 기존 A/B/C 패키지 + C의 변환·계산 규칙.

- [ ] **B01 환경·버전:** Pandas·PySpark·Delta Lake·MySQL 버전과 명령 기록.
- [ ] **B02 원본 인수·Bronze 보존:** 오염 원본·명세서·해시·파일명·행 번호.
- [ ] **B03 Bronze Delta:** 오염 상태로 저장·조회하고 값·건수 대조.
- [ ] **B04 모델·ERD:** C와 사전 합의, 개념·논리·물리 ERD·키 일치.
- [ ] **B05 정제 실행 연결:** C의 규칙·기존 복구 코드를 파이프라인에 연결.
- [ ] **B06 Silver Delta:** 기업·공시·재무·주가·수급과 검토 상태 저장.
- [ ] **B07 Gold Delta:** C의 계산을 실행해 분석·AI 입력 테이블과 버전 저장.
- [ ] **B08 MySQL 레이어:** `tz_bronze`·`tz_silver`·`tz_gold`·`tz_meta` DDL·적재.
- [ ] **B09 조회 API:** 기업 목록·일별 추이·보고기간 비교·품질 상태 제공.
- [ ] **B10 SQL 검증:** 건수·키·NULL·표준·도메인·코드·금액 보존 검사.
- [ ] **B11 재실행 대사:** Delta 버전별 MySQL 값 대사·중복 적재 확인.
- [ ] **B12 재현·인계:** 입출력 해시·실행 기록·DB 덤프·복원법·API 명세.

제출: Delta 테이블·MySQL DB·API·SQL 검증·덤프/복원법. 완료: Delta를 실제 읽고 쓰고, MySQL 대사·API·재실행이 재현된다.

## C — 김형준 / Pandas 분석·시각화

입력: 오염 원본·명세서 + Bronze Delta + 기존 재무·주가·수급.

- [ ] **C01 원본 Pandas 진단:** 결측·중복·형식·코드 혼용·명명 위반을 파일·컬럼별 수치화.
- [ ] **C02 명세서 대조:** 정상 선택 결측과 결함, 검출 기준·분모·근거 구분.
- [ ] **C03 표준 사전:** 단어·용어·도메인·코드·조합·타입·길이·허용값.
- [ ] **C04 변환·미해결 정책:** B의 실행 코드와 격리·보존·재조회 상태 전달.
- [ ] **C05 재무 기간·계정:** 누적·3개월·기말, 연결·별도, 계정 근거 검증.
- [ ] **C06 주가·수급·시점:** 수급 주 단위, 공시 전 정보 사용 방지.
- [ ] **C07 실적 변화:** 전년동기 변화·영업이익률, 적자·0 기준 예외.
- [ ] **C08 현금·시장 비교:** 현금흐름 변화와 같은 기간 주가·외국인·기관 수급.
- [ ] **C09 동반 개선·괴리:** 판정·임계값·분석 불가·추가 검토 근거 문서화.
- [ ] **C10 시각화:** 주가·실적·현금·수급의 축·단위·범례·예시를 A에게 전달.
- [ ] **C11 AI 입력 규격:** 특징·결측·시간순 분할, 지도학습 시 정답 정의.
- [ ] **C12 Pandas 검증·개선:** 처리 전후와 B의 SQL 결과 대조·잔여 이슈 설명.

제출: 프로파일링·사전·분석 코드·지표 정의·시각화 샘플. 완료: 지표가 원본으로 추적되고 기간·단위·미해결 상태·SQL 대조 근거가 있다.

## G — 서로 전달할 것

- [ ] **G01 C→B 분석·변환 계약:** 컬럼·타입·단위·계산식·NULL·예외·격리. 증빙: 사전·실행 모듈·지표 정의.
- [ ] **G02 B→A API 계약:** 목록·시계열·보고기간·품질 필터·응답. 증빙: 명세·정상/오류/결측 샘플.
- [ ] **G03 C→A 시각화 계약:** 예시·축·단위·기간·범례·괴리/분석 불가 설명. 증빙: 그래프·컬럼 대응·해석 가이드.
- [ ] **G04 B↔C 검증 합의:** 동일 입력·기간·단위 SQL/Pandas 대조. 증빙: 양쪽 결과·차이·해결 기록.
- [ ] **G05 A·B·C 최종 연결:** 동일 기업·기간의 원본·Gold·MySQL·API·화면 일치. 증빙: 통합 검사·화면 캡처·잔여 이슈.

먼저 지표·기간·단위·응답을 합의한다. A는 샘플 화면, B는 저장·API, C는 프로파일링·Gold를 병렬 진행한다. 마지막에 실제 API로 같은 사례를 검수한다.

## F — 최종 제출

- [ ] **F01 원본·명세·AS-IS:** C 주도/B 지원. 오염 원본 5개 결함 유형의 수치·근거.
- [ ] **F02 표준 사전:** C 주도/B 반영. 단어·용어·도메인·코드·조합·타입·길이·허용값.
- [ ] **F03 모델·MySQL:** B 주도/C 검토. 개념·논리·물리 ERD·정규화·키·관계·레이어 구현.
- [ ] **F04 실제 Delta:** B 주도. 3레이어 저장·조회·트랜잭션 로그·버전 증거.
- [ ] **F05 SQL/Pandas:** B·C 공동. 건수·키·표준·도메인·코드 위반 대조·변환 단위 차이 설명.
- [ ] **F06 분석·AI 데이터셋:** C 주도/B 저장. 컬럼·기간·결측·분할·필요 시 정답 확정.
- [ ] **F07 화면까지 값 일치:** A 주도/B·C 검토. 단위·공시 시점·NULL·검토 상태 보존.
- [ ] **F08 재현 묶음:** B 취합/전원 확인. 코드·해시·기록·DB 복원법·잔여 이슈.

Pandas는 처리·집계, 그래프 라이브러리는 시각화를 담당한다. PASS는 모든 결측의 해결을 뜻하지 않는다. 기존 미연결·검토 상태를 보존한다.

## 증빙을 남기는 방법

체크북의 기존 작업에 더해 [보완 업무 M01~M14](missing-work.md)를 역할별로 수행한다. 원본 미확보는 확보 요청으로, 문서·코드·검사 미작성은 담당자의 추가 작업으로 연결한다. 기존 47개 체크 ID는 유지하며 누락 자료가 해결됐다고 자동 체크하지 않는다.

각 역할은 `docs/roles/A.md`·`B.md`·`C.md`에 작업 ID, 코드/결과 파일, 실행 명령, 실제 결과, 기준 커밋·데이터 버전, 미해결을 기록한다. 대조·통합은 `docs/handoffs/`에 남긴다. 기록 없이 체크만 완료 처리하지 않는다.
