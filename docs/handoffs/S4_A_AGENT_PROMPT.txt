[A 담당 에이전트에게 — S4 실제 API 수신·연결·검증 요청]

너는 TEAM ZERO의 A 프론트엔드 담당 에이전트다. 기존 화면과 C 계산값 대조 결과를 보존하면서 B의 실제 API 1.1.0을 연결하고, 브라우저·화면·CSV 대조까지 진행해 줘. 계획에 그치지 말고 가능한 구현·검사를 수행해 줘. 진행 전에 방법을 설명하고, 끝나면 수정 내용과 실제 결과를 알려 줘.

이번 요청은 로컬 파일 수정·실행·검증·인계 기록이다. 커밋·push·PR 생성/수정/병합·git merge/rebase/cherry-pick은 하지 마. reset·clean·강제 checkout·자동 stash로 기존 작업을 지우지 마. 다른 에이전트나 외부 메신저에 메시지도 보내지 마. 원본 데이터·DB·비밀값은 변경하거나 공유하지 마.

3. 실행 환경과 C 계산 묶음

B API는 Python 3.12, C 재계산은 Python 3.13.15와 C의 analysis/requirements.txt를 사용한다. 기존 환경을 먼저 확인하고 별도 가상환경을 유지해 줘. backend/service/setup.ps1의 -Python에는 실제 Python 3.12 실행파일을 지정해 줘. 기본 python이 3.13이면 그대로 넘기지 마. 이미 backend/service/.venv에 적합한 환경이 있으면 재사용해 줘.

A가 이미 재현한 C 결과가 있으면 재사용해 줘. 필요한 파일은 schema.json, validation.json, g_fin_rpt_analysis.csv, g_stock_daily_analysis.csv다. C 계산 버전은 c-gold-0.1.0, 확인한 전달 SHA는 6a61b132f54bf6a2553ad323e57e73b1cda09e65다.

C 결과가 없으면 현재 검증된 C 코드에서 고정 입력을 읽어 별도 폴더로 재생성해 줘. C 코드와 결과가 모두 없으면 필요한 전달본만 구체적으로 요청하고 A 어댑터 등 독립 작업은 계속해 줘.

프로젝트 루트 PowerShell에서 실제 C 출력 위치에 맞춰 다음을 실행해 줘. 출력 폴더가 이미 있으면 기존 실험을 보존하고 새 이름을 사용해 줘.

& .\backend\service\.venv\Scripts\python.exe -X utf8 .\backend\service\pack_c_analysis.py --source .\build\analysis --output .\build\c_api_artifact
& .\backend\service\.venv\Scripts\python.exe -X utf8 .\backend\service\run.py --backend csv --analysis-dir .\build\c_api_artifact

서버는 http://127.0.0.1:8000 이며 /health, /docs, /openapi.json으로 확인한다. 종료는 실행 창의 Ctrl+C다. 이미 사용 중인 포트를 강제로 종료하지 말고 직접 시작한 서버만 관리해 줘. .env는 자동으로 읽지 않으므로 쉘 환경변수나 CLI 옵션을 사용해 줘.

프론트 설정은 VITE_DATA_MODE=api, VITE_API_BASE_URL=http://127.0.0.1:8000이다. 실제 화면 주소를 B의 TZ_CORS_ORIGINS에 넣어 줘. API 실패 시 합성 샘플로 자동 대체하지 마.

팀원 PC에서는 로컬 CSV와 검증 C 묶음으로 먼저 연결한다. B PC의 MySQL 비밀번호는 필요하지 않아. 신규 C 두 테이블의 MySQL 적재·조회 검증은 B에서 미실행이므로 화면 연결 성공을 DB 전체 완료로 기록하지 마.

4. A 소유 API 어댑터에서 맞출 차이

- 기존 샘플의 a-proposal-1 validator를 실제 meta.api_version=1.1.0 계약에 맞춰 줘. data_end는 data_final_date, calc_version은 calculation_version에 대응한다.
- synthetic=false, input_version, data_version, calculation_version, analysis_data_version으로 응답 간 스냅샷을 확인해 줘. endpoint별 total·limit·offset·price_base_date 차이를 버전 불일치로 오인하지 마.
- endpoint별 쿼리만 전달해 줘. daily는 start/end이므로 화면 as_of를 end로 매핑한다. financials는 report_code=report, fs_div=basis, as_of, 정수 year를 쓴다. year=all이면 year를 생략하고 빈 market도 생략한다. compare/evidence는 as_of를 쓴다.
- compare/daily의 C 값은 각 행.analysis, financials의 C 값은 각 보고서.analysis에 있다. 기존 normalizeCRow를 활용하려면 먼저 중첩을 매핑해 줘. 원래 금액·보고서·연결 정보·기간·상태·검토 플래그는 보존해 줘.
- rev_yoy_rt→revenue_growth_rt, event_excess_rt→excess_return_rt 같은 별칭은 표현 변환으로만 적용하고 계산값을 바꾸지 마.
- evidence의 data는 배열이 아닌 객체이며 observation, financial_report, price_source, pit_rule로 구성된다. 화면 근거 구조로 맞추고 없는 원천 값은 미제공으로 표시해 줘.
- 업무 금액·수량·비율은 정밀도 문자열이고 NULL과 0은 다르다. 큰 금액을 JS Number로 일괄 변환하지 말고 원·주·%·%p 단위를 명확히 보여 줘. YTD·ASOF·Q3M과 CFS/OFS를 구분하고 반복된 재무를 일별 합산하지 마.
- 요청 기준일과 실제 관측일 trd_dt를 구분해 줘. 휴일에 직전 관측값이 반환돼도 요청일과 다르다는 이유만으로 거부하지 마. 공시일 < 거래일, 공시 당일 제외 규칙을 유지해 줘.

5. 가격·시장 차트와 다운로드

daily는 stock_base100, market_base100, price_base_date, price_chart_stts_cd와 meta.price_base_date를 제공한다. 조회 구간 전체에서 종가와 지수가 같은 날 모두 유효한 첫 관측을 각각100으로 삼는다. 페이지 이동은 기준일 유지, 조회 시작일 변경은 재계산이다.

이 값을 그대로 그려 줘. 화면에서 전체 기간으로 다시 정규화하거나 두 계열에 다른 기준일을 쓰지 마. 조회 차트 기준일과 C의 공시 후 성과 event_base_dt/event_excess_rt는 서로 다른 구간이다.

OK/BEFORE_BASE_DATE/NO_COMMON_BASE/PARTIAL과 NULL을 구분해 줘. 결측을 0으로 그리거나 보간하지 마. 빈 구간은 data=[]와 price_base_date=null이다.

다운로드 구분:
- /exports/stocks/{code}/chart.csv: 동일 기준100과 기준일을 포함한 차트 값
- /exports/stocks/{code}/daily.csv: 기존 Gold 원래 컬럼
- /exports/stocks/{code}/financials.csv: 보고서×지표×기간 유형, 보고서당94행
- /exports/analysis/g_fin_rpt_analysis.csv, g_stock_daily_analysis.csv: C 계산 결과 전체

6. 실제 브라우저·화면·CSV 수용 검사

B의 기존 검사(B 자동51개, C18개, 실제 HTTP16개)와 네가 이번에 실행한 검사를 구분해 줘. 프론트의 기존 unit/build/e2e와 수정한 어댑터에 필요한 검사를 수행해 줘. fixtures만으로 실제 API 연결 성공을 선언하지 마.

실제 브라우저 network가 API를 호출하는지, 로딩·취소·빠른 필터 변경·정상·빈 결과·404/422/409·오류 복구·NULL/0·큰 금액·모바일·출처·다운로드를 확인해 줘.

공통 대조 사례:
- 삼성전자005930, 기준일2026-06-30, 차트 구간2026-06-01~2026-06-30
- price_base_date=2026-06-01, 첫날 두 계열100.00000000
- 마지막날 stock_base100=93.80281690, market_base100=96.45099552
- 누적 매출333605938000000, 영업이익43601051000000, 순이익45206805000000, 영업현금85315148000000
- rev_yoy_rt=0.10880093, event_excess_rt=0.32769823, co_move_cd=IMPROVE_STRONG, joint_improve_yn=N

전체 기대값은 fixtures/api/s4/expected_values.json을 따른다. 프로젝트의 검증 자료 값이며 실시간 시장값이 아니다. API→화면 표시→다운로드 CSV에서 값·단위·기간·NULL이 같은지 비교해 줘.

247540/2026-04-16은 가격 존재·수급NULL·invstr_exist_yn=N을 확인해 줘. 2026-06-06 시작 조회는 첫 유효일2026-06-08이 되는지, 페이지를 바꿔도 기준이 같은지, 휴일 기준일의 실제 거래일을 검사해 줘. 공시 당일 보고서 제외와 부적격 기간 상태 보존도 확인해 줘.

C 묶음을 연결하지 않은 모드의 PENDING_C_DELIVERY, analysis=null, 신규 CSV409는 지원 상태로 구분해 줘. 샘플의 정상·빈 결과·오류 응답은 계약 참조이고 실제 API 검사를 대신하지 않는다.
