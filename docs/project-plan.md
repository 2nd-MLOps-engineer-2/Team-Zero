## 1. 하나의 공동 목표

**기업 실적·투자자 수급·주가 동행/괴리 분석 대시보드**를 완성한다.

사용자가 보유 20종목 중 종목과 기준일을 선택하면, 그 시점에 공개되어 있던 기업 실적, 외국인·기관 수급, 시장 대비 주가 성과를 함께 보여준다. 실적 개선과 주가 움직임이 같은 방향인지 엇갈리는지 탐색하고 원자료와 계산 근거까지 확인할 수 있게 한다.

최종 시연 흐름:

1. 기준일·시장·종목 선택
2. 기업 실적과 시장 대비 성과 비교
3. 외국인·기관 수급 확인
4. 종목 상세에서 공시·실적·가격 추이 확인
5. 분석 근거 확인 및 결과 CSV 다운로드

## 2. Bronze: 원본을 보존하는 계층

### 목적

전달받은 데이터를 당시 형태로 보존하고, 이후 결과를 원천 파일과 행으로 추적할 수 있게 한다.

### 내용

- A 영역: 기업, 공시목록·원문 수집 상태, 재무 보고서·지표·상세 원본.
- B 영역: 종목, 주가, 시장 지수, 투자자 매매, 외국인 보유, CFD 잔고 원본 및 수급 JSON.
- 원본 컬럼명·빈값을 보존하고 적재 행 번호·파일·해시·실행 정보를 기록.
- 제공 모델의 DB는 `tz_bronze`, 테이블은 18개다. 이는 인계 보고서·DDL 기준이며 현재 폴더의 별도 DB 덤프를 복원해 재확인한 수치는 아니다.

### 현재 상태

인계 보고서에 과거 구현 완료가 기록되어 있으며 DDL·프로파일·검증 기록은 저장소에 포함되어 있다. **Bronze의 A/B 입력 CSV 18개와 DB 덤프는 미포함**이므로 clone만으로 원래 Bronze 전체를 복원·재실행할 수 있다고 표현하지 않는다. 특히 C의 AS-IS는 A/B 인계본 기준이며 최초 교환 오염 원본과 구분한다. 현재 Gold 개발은 제공된 Silver를 그대로 활용한다.

## 3. Silver: 표준화된 관계형 데이터를 제공하는 계층

### 목적

코드·명명·자료형과 식별키·관계를 통일하고, 분석 가능한 통합 데이터와 가용성 정보를 제공한다.

### 수행된 내용

- 표준 단어·용어·도메인·코드 사전 적용.
- 종목코드·기업코드의 선행 0 보존, 날짜·비율·금액 단위 통일.
- 기업-종목 매핑, 재무 보고서-지표-상세 관계 구성.
- 재무 지표를 보고서·지표·기간 유형당 한 행으로 정규화.
- 가격·수급 키 합집합과 데이터 부재 사유 보존.
- 공시 시점 연결 적격 여부와 기간 비교 적격 여부 관리.
- 원천 파일·행·버전과 품질 이슈 추적.

### 핵심 관계

- 기업 → 공시·재무 보고서: `corp_cd`, 1:N.

## 4. Gold: 분석 목적에 맞는 데이터와 서비스를 완성하는 계층

### 기존 Gold 초안

| 테이블 | 크기 | 제공 내용 |
|---|---|---|
| `g_ai_stock_daily` | 17,440행 × 34열 | 가격·지수·최상위 투자자 수급·보유·CFD·당시 이용 가능 재무의 일별 통합 |
| `g_fin_rpt_mkt_smry` | 320행 × 21열 | 재무 보고기간의 가격 성과·수급 요약·누적 실적 |

기존 Gold를 분석 기반으로 사용한다. 보고기간 시장 요약은 해당 보고기간의 동시 관측값이며, 공시 이후 반응과 구분한다.

### 신규 Gold 설계

| 테이블 | PK·행 단위 | 주요 내용 | 목표 행 수 |
|---|---|---|---:|
| `g_fin_rpt_analysis` | `fin_rpt_id`, 보고서당 1행 | 당기·전년동기 실적, 성장률·이익률·부채비율·현금흐름 비율, 공시일, 기간·연결구분·계산 상태·원천 버전 | 320 |
| `g_stock_daily_analysis` | `(stock_cd,trd_dt)`, 종목·일당 1행 | 기간별 성과·시장 대비 성과, 누적 수급, 보유율 변화, 변동성, 시점 보고서 ID, 공시 후 성과·동행/괴리 분류·가용성·계산 버전 | 17,440 |

관계는 일별 분석의 `fin_rpt_id` → 보고서 분석이다. 보고서 분석에 값이 있어도 공시 전 날짜에 연결하지 않는다. 분석 불가 행을 삭제해 목표 건수를 맞추는 방식 대신 NULL과 사유를 보존한다.

### 지표 정의

| 지표 | 계산식 | 조건·표시 단위 |
|---|---|---|
| 전년동기 매출 성장률 | `(REVENUE.YTD / REVENUE.PRIOR_YTD - 1) × 100` | 동일 보고서의 비교 기간, 비교 적격, 전년 매출 > 0 / % |
| 영업이익률 | `OPERATING_PROFIT.YTD / REVENUE.YTD × 100` | 매출 > 0, 동일 기간·연결구분 / % |
| 영업이익 증감액 | 당기 YTD 영업이익 − 전년동기 YTD 영업이익 | 적자·흑자 전환 상태 병기 / 원 |
| 부채비율 | `TOTAL_LIABILITIES.ASOF / TOTAL_EQUITY.ASOF × 100` | 자본 > 0, 자본 ≤ 0은 별도 상태 / % |
| 영업CF/매출 | `OPERATING_CASH_FLOW.YTD / REVENUE.YTD × 100` | 현금흐름 기간 검증, 매출 > 0 / % |
| 5·20관측일 가격 성과 | `close[t] / close[t-n] - 1` | n개 관측 간격 확보, 제공 종가 기준 / 화면 % |
| 시장 대비 성과 | 종목 성과 − 해당 시장 지수 동일 시작·종료일 성과 | 두 성과의 차이 / %p |
| 투자자 순매수 비율 | 기간 순매수 수량 합 / 동일 기간 거래량 합 × 100 | TOP_LEVEL 유형별, 분모 > 0, 누락 없는 구간 / % |
| 외국인 보유율 변화 | `(hold_rt[t] - hold_rt[t-20]) × 100` | 두 시점 값 존재 / %p |
| 20일 변동성 | 최근 20개 유효 일별 수익률의 표본 표준편차 × 100 | 일별 표준편차 / % |
| 공시 경과일 | 선택일 − 연결 보고서 공시일 | 달력 일수 / 일 |

DB·API의 수익률·비율은 소수 비율로 통일하고 화면에서 100을 곱해 표시한다. 금액은 원, 수급은 주 단위로 관리한다. 큰 정수 금액은 프론트엔드 정밀도 손실을 피하도록 API 표현 방식을 합의한다.

### 동행/괴리 초기 분류

기준일에 이용 가능한 최근 보고서의 전년동기 매출 성장률과, **해당 공시 전 마지막 관측 종가부터 기준일까지의 시장 대비 성과**를 비교한다. 고정 20일 추세는 별도 지표다.

| 매출 성장률 | 공시 후 시장 대비 성과 | 표시 |
|---|---|---|
| > 0 | > 0 | 개선·강세 동행 |
| > 0 | < 0 | 개선·약세 괴리 |
| < 0 | > 0 | 둔화·강세 괴리 |
| < 0 | < 0 | 둔화·약세 동행 |

0은 중립, 비교 부적격·가격 부재는 판단 불가로 구분한다. 임계값 0은 초기 탐색 규칙이며 분포를 확인한 뒤 변경할 경우 계산 버전을 남긴다. 서로 다른 공시 경과 기간을 사용하므로 비교표에 경과일과 관측 구간을 표시한다. 수급은 보조 정보로 제공한다.

## 5. 대시보드 및 API

| 화면 | 핵심 기능 |
|---|---|
| 종목 비교 | 기준일·시장 필터, 실적/시장 대비 성과 사분면, 수급 색·비교표 |
| 종목 상세 | 가격·지수 기준값 100 추이, 투자자 순매수, 보유율, 실적 추이, 공시 표시 |
| 실적 비교 | 동일 연도·보고서 유형·연결구분의 성장률·이익률·부채비율 |
| 근거 상세 | 보고서 ID·공시일·분자·분모·구간·누락 사유·버전, CSV 다운로드 |

초기 API 계약안:

- `GET /stocks`: 종목 목록
- `GET /stocks/compare?as_of=YYYY-MM-DD`: 기준일 비교
- `GET /stocks/{code}/daily?start=...&end=...`: 일별 분석
- `GET /stocks/{code}/financials`: 보고서별 실적 분석
- `GET /analysis/{code}/evidence?as_of=YYYY-MM-DD`: 계산 근거
- `GET /exports/...`: 분석 결과 다운로드

응답에 조회 기준일, 데이터 최종일, 관측 수, 단위, 가용성, 계산 버전을 포함한다. 화면 기본 기준일은 데이터 최종일인 **2026-06-30**으로 둔다.

## 6. 분석 범위와 제한

- 주가 20종목 × 872일, 재무 2022~2025년 범위다. 전체 시장 결과나 실시간 결과로 표시하지 않는다.
- 시점 연결·동일기간 비교 적격 보고서는 각각 259건이고 61건은 부적격이다. 두 플래그를 목적에 맞게 확인한다.
- 기존 일별 Gold 재무 가용은 15,833행, 미가용은 1,607행이다.
- 기존 기간 요약의 전체 가격 커버리지는 Y 240건, N 80건이다. 비교 적격과 별개 조건이므로 교집합을 계산한다.
- 핵심 재무지표 YTD·ASOF는 각 320건에 존재하지만 매출·영업이익·순이익 Q3M은 각 240건만 존재한다. MVP는 YTD 전년동기 비교를 우선한다.
- CFD는 2023-08-31부터 제공되어 가격 기준 3,721행이 비어 있다. 가격만 있는 키는 `247540 / 2026-04-16` 1건이다.
- 수급의 기관 합계와 기관 세부 7유형을 더하면 이중 계산된다. 투자자 간 합계에는 TOP_LEVEL만 사용한다.
- 재무 상세 당기금액 빈값 2,202행, 지표 충돌 표시 보고서 1건 등은 관련 지표의 사용 가능 여부에 반영한다.
- 원문 관리에는 752건의 다운로드 상태가 기록돼 있지만 이번 인계 폴더에는 해당 원문 ZIP이 없다. 원문 NLP는 후속 범위다.
- 수정주가 여부·기업행동 조정 이력이 명시되어 있지 않다. 성과는 제공 종가 기준으로 표시한다.
- 종목 마스터 발행주식 수를 모든 과거 날짜에 적용해 시가총액·PER·PBR 시계열을 확정하지 않는다.
- 공시일 < 거래일 조건을 유지한다. 공시목록에 없는 보고서의 공시일을 기간 종료일로 대체하지 않는다.
- 동행/괴리는 설명 가능한 탐색 분류다. 투자 권유·인과관계 증명·수익률 예측 성능을 의미하지 않는다.

## 7. 팀원별 역할과 공동 인터페이스

| 담당 | 주요 업무 | 완료 산출물 |
|---|---|---|
| 김형준 — Pandas 분석·시각화 | 보고서 피벗, 지표·관측 윈도 계산, 시점 적용, 분류, 값 검증·차트 설계 | Gold 계산 모듈, 지표 명세, 그래프 예제, 대사 결과 |
| 이어진 — 프론트엔드 | 비교·상세·근거 화면, 필터, 차트·툴팁·다운로드 연동 | 실제 API로 동작하는 대시보드 |
| 설호현 — 백엔드 | Gold DDL·적재, 필터·조회·다운로드 API, 실행·버전 관리 | Gold 테이블, API 명세·샘플 응답, 실행 절차 |

공동으로 행 단위·컬럼명·단위·NULL 사유·시점·버전 및 샘플 응답을 먼저 확정한다. 지표는 분석 모듈에서 계산하고, 화면에서 별도 업무 계산으로 수치를 바꾸지 않는다.

## 8. 개발 순서와 완료 기준

개발·전달·합치기는 [S0~S5 통합 진행표](integration-status.md)와 [브랜치 절차](integration-workflow.md)를 따른다. B API→A 화면은 S4의 고정 handoff와 A review 브랜치에서 확인하고, 각 단계 결과는 integration에 모아 S5 전체 확인 후 main 반영을 준비한다.

각 단계는 [누락·미구현 보완 업무 M01~M14](missing-work.md)와 함께 진행한다. Bronze의 입력 확보·Delta 증빙, Silver의 실제 저장·잔여 규칙, Gold의 계약·계산·API·화면·AI 입력 규격을 각 역할이 추가하고 증빙으로 확인한다.

1. **정의 확정:** 지표·시점·분류·단위와 샘플 API 응답 확정. 체크북 C01~C06의 기존 원본 진단·표준 사전·기간 검증 증빙을 재사용하고 부족한 부분만 보완.
2. **분석 구현:** 보고서 분석 → 일별 분석 순서로 생성, 1종목 차트 예제로 검토.
3. **서버·화면 연결:** Gold 적재와 실제 API를 비교·상세·근거 화면에 연동.
4. **통합 검증:** 공시 전후, 누락, 분모 0, 최초 윈도, 연결구분·기간 비교 확인.
5. **시연·제출:** 선택 → 비교 → 상세 → 근거 → 다운로드의 전체 흐름 시연.

완료 조건:

- 보유 20종목을 기준일·기간으로 비교하고 상세·근거를 확인할 수 있다.
- 신규 일별 분석 17,440행·보고서 분석 320행을 유지하고 PK 중복이 없다.
- 시점 누수·기관 이중 합산·재무 반복 합산이 없다.
- 대표 지표를 Silver에서 독립 계산한 값과 대사하고 API·화면·다운로드가 일치한다.
- NULL·분모 0·윈도 부족·기간 미검증 상태가 실제 0과 구분된다.
- 지표 명세, Gold 모델·관계, API 명세, 실행 안내, 검증 결과가 남아 있다.
- 실제 Bronze·Silver·Gold Delta 저장·조회와 `_delta_log`·버전 증빙, Delta↔MySQL 건수·값 대사가 남아 있다.
- 원본 AS-IS 5개 결함 유형 수치, 표준 사전, 개념·논리·물리 ERD, SQL·Pandas 대조, AI 입력 규격과 재현 묶음을 F01~F08 기준으로 확인한다.

## 10. 근거와 기술 범위

수치는 인계본의 `04_output/silver/*.csv`, `04_output/gold/*.csv` 전체에서 확인했다. 관계·타입은 `03_model/ddl/02_silver.sql`·`03_gold.sql`, 의미는 표준 사전과 통합품질 보고서, 시점 선택은 `code/run_pipeline.py`를 참고했다. 기존 검증 기록과 출력 해시를 대조했다.

인계 모델은 MySQL의 `tz_bronze`·`tz_silver`·`tz_gold`·`tz_meta` 구조다. Medallion 계층을 MySQL에 구성한 것과 실제 Delta Lake 기술 구현은 구분한다. 체크북 B03·B06·B07·B11·F04에 따라 실제 Delta 저장·조회·버전 증빙과 MySQL 대사를 최종 범위에 포함한다. 기존 Silver를 다시 만드는 플랫폼을 개발하지 않고 기존 모델·코드를 연결한다. 본 문서 등록은 데이터·DB·Delta·대시보드 구현 완료를 의미하지 않는다.
