# A·B·C 공유 계약

B의 [API](api.md)·[실행환경](runtime.md)은 구현·로컬 검증된 계약이며 A·C 수신 확인을 기다린다. [C 결과 전달 형식](analysis-artifact.md)은 합의 전 제안이다. C 분석·시각화 계약과 전체 기능 승인은 별도다.

계약 초안은 [실제 데이터 안내](../docs/data-guide.md)와 [컬럼 사전](../docs/data-catalog.md), `data/03_C_integration_20261014/`의 실제 CSV·표준 사전을 바탕으로 작성한다. 새로운 임의 컬럼명이나 예제 값을 실제 파일에 존재한다고 가정하지 않는다.

| 계약 | 작성 주도 | 확인 | 저장 위치 |
|---|---|---|---|
| G01 분석·변환 | C | B | `contracts/analysis.md` — 구현 시작 시 작성 |
| G02 API | B | A·C | `contracts/api.md`, `fixtures/api/` — 구현 시작 시 작성 |
| G03 시각화 | C | A | `contracts/visualization.md` — 구현 시작 시 작성 |
| G04 검증 | B·C | 공동 | `docs/handoffs/G04-validation.md` |
| G05 통합 | A·B·C | 공동 | `docs/handoffs/G05-integration.md` |

## 모든 계약에 포함할 항목

상태(제안/합의/구현/검증), 버전·작성자·확인자, 입력·출력, 행 단위·PK, 컬럼·자료형·단위, 기간·시점, NULL·오류 정책, 정상·빈값·실패 예제, 실제 검사와 결과를 기록한다. 예제는 합성 여부를 표시한다.

API의 비율은 소수 비율, 금액은 원, 수급 수량은 주로 통일한다. 큰 금액의 JSON 표현과 날짜 형식을 명세하고, 표시는 A가 %·%p 등으로 변환한다. 표준 컬럼명과 계산은 C의 계약을 따른다.

## 짧은 handoff 양식

실제 코드가 합쳐지는 인계에는 [단계별 전달 양식](../docs/handoffs/TEMPLATE.md)과 [진행표](../docs/integration-status.md)를 사용한다. 아래 짧은 양식은 요청 초안용이다. 검사한 전달 브랜치·고정 SHA·실행법·PR, 수신자가 자기 작업에 합쳐 확인한 결과까지 있어야 해당 단계 수신 완료다.

```text
작업/요청 ID:
요청자 → 대상:
상태·기준 브랜치·SHA·데이터 버전:
필요한 파일/인터페이스:
입력 → 기대 출력 예:
기간·단위·NULL·예외:
실제로 수행한 검사와 결과:
영향 및 남은 의존성:
다음 담당자가 바로 실행할 명령:
```

다른 역할을 기다리며 가능한 작업은 계속한다. 명령을 아직 만들지 않았다면 `미구현`으로 적는다. 요청 문서를 남긴 것만으로 상대방이 확인·합의했다고 표시하지 않는다.
